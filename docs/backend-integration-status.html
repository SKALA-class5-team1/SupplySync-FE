2. 임시로 둔 가정 (백엔드 확인 필요)

  1. 승인 화면은 RFQ 상세 응답의 task_id를 쓴다. 응답에 없으면 승인 버튼이 비활성화된다.
  2. STEP_START/STEP_END 데이터는 step 또는 name 필드에 단계명이 있다고 본다.
  3. 분석 결과(review)와 견적(quotes[]) 내부 필드명은 모른다. 지금은 JSON 그대로 보여 준다.
  4. RFQ 목록 응답은 배열이고, 각 항목에 rfq_id, rfq_number, status가 있다고 본다.

3. 아직 못 한 것

  • 분석 결과 화면: 이슈 7건, 가정, 고객 질의서, 계약 리스크, 부족 부품, 대안 4종(추천 표시)을 항목별로 나누어 보여 주기
  • 고객 견적 화면: 단가·연도별 단가·납기·유효기간·조건을 표로 정리
  • 요구 확인(담당자) 화면: assumptions 입력 후 제출
  • 승인 더블 클릭 방지 (현재는 버튼 비활성화만 함)
  • 실제 백엔드 연동 검증 (Swagger JSON http://localhost:8080/v3/api-docs/1-web 확인 후 DTO 타입 생성)

4. 확인 방법

  • cd /Users/jh/projects/supplysync && npm install && npm run dev
  • 백엔드 기동: SPRING_PROFILES_ACTIVE=demo ./gradlew bootRun
  • http://localhost:5173/login에서 데모 계정 hb_buyer01(고객) 또는 ds_sales01(담당자), 비밀번호 demo1234

5. 결정이 필요한 것

  1. Swagger JSON 공유 가능 여부 (분석·견적 DTO 타입 자동 생성)
  2. SSE 인증은 현재 fetch 스트림으로 해결했다. @microsoft/fetch-event-source로 바꿀지 여부
  3. CORS 대신 Vite 프록시를 계속 쓸지 여부 (현재 프록시 사용)
